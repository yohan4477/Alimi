## 구현 후속 — 같은 탭 초안 연결 1단계 (2026-10-23)

본인 이야기에서 지역을 명시적으로 선택하고, 개인 텍스트는 URL 대신 sessionStorage에 둔 채 불투명 draft ID로 이어받는 기능을 추가한다. 대상 홈에서 아직 비공개인 초안을 보여주고 실제 지역 대화방을 선택한 뒤 기존 글쓰기에서 제목·본문을 편집·직접 게시한다. 작성 중 수정 내용을 같은 탭에서 복구하고 성공 응답 또는 명시적 삭제 후 초안을 지운다. 요청 진행 중 중복 클릭을 막는다. 방 목록 실패는 재시도, 빈 목록은 새 방 만들기를 제공한다.

이 단계는 **브라우저 내 초안 전달**이다. 서버 handoff 토큰·계정 연결·크로스 기기·서버 멱등 게시·관련 대화 자동 매칭은 아직 없다. 기존 community_open에 source=beauty_play와 handoff_id만 붙이며 원문은 보내지 않는다. 이벤트 수신·순차 통합 퍼널 완료를 보장하지 않는다. 아래 5절의 서버 계약은 후속 요구로 유지한다. 초안은 24시간 이후 읽기를 거부·정리하며, 브라우저가 닫힌 탭을 복원하는 방식에 따라 저장 매체 수명은 달라질 수 있다.

## 1. 문제와 결과

흥미로운 게임을 만들더라도 실제 고민·경험·대화·구매 판단으로 연결되지 않으면 일회성 트래픽만 남는다. 목표는 게임 선택을 사용자의 실제 피부 정보로 오인하지 않으면서, 본인이 말한 고민과 경험을 서울뷰티의 유용한 활동으로 이어주는 것이다.

성공은 세 층으로 본다. 획득은 유효 게임 참여와 친구 유입, 활성화는 실제 첫 대화·답변·재방문, 수익은 귀속 확인된 승인 순제휴 수수료다. 게임 완료·링크 클릭·자가 구매 응답은 수익이 아니다. 현재 승인 매출 목표값·전환율 실적은 미확정·미측정이다.

## 2. 범위와 실제 기준선

- 운영 게임: https://seoulbeauty.me/beauty-play/ . 커뮤니티: /kr, /us. 기존 3탭 구조를 유지한다.
- 배포 기준: main 08df28a, PR #167. 운영 도메인에서 세션·테스트 답 저장·초대·새 친구 답·비교 공개 검증. 테스트 데이터는 일반 실적에서 제외한다.
- 게임 프런트는 web/beauty-play/, 정적 빌드는 dist/beauty-play/. api/beauty-play.js는 허용된 게임 API만 원래 D1 백엔드로 전달한다.
- D1 게임 저장과 Supabase 커뮤니티는 별도다. 같은 도메인이어도 계정·답변·주문이 자동 통합되지 않는다. 커뮤니티 인증 쿠키를 게임 백엔드로 전달하지 않는다.
- 개인 답변 정리·복사는 구현. /kr 또는 /us 홈 진입은 구현. 관련 대화 자동 매칭·초안 전달·통합 귀속은 미구현.
- 게임 결과 제품 링크는 판매처 직접 이동이다. 원래 Sites /community의 clickref·주문 업로드 시제품은 운영 게임→실제 커뮤니티 전체 연결의 증거가 아니다.
- 기존 커뮤니티 코드의 상품·후기·저장·판매처 기능과, 운영 DB 지역 마이그레이션·한국 대화/판매처 데이터·실제 주문 정산 검증 상태를 구분한다. 이전 운영 권한 차단을 이 문서로 해소하지 않는다.

## 4. 콘텐츠·상품 계약

초기 모나리자·마담 X 두 상황. 전체 여섯 인물·24방향을 한꺼번에 모집하지 않는다. 방향당 실제 후보가 충분한지 먼저 점검한다. 현재 게임 제품 19종이며 립 최초 후보는 5개, 다른 제품군은 2개 또는 방향별 2~3개 수준일 수 있다. 블러셔·아이섀도는 후보 확보 전 노출하지 않는다.

콘텐츠 필드: character_id, scenario_id, situation_version, fictional_condition, question_type(same_category/cross_category_priority), advice_id, candidate_set_id, locale, region, published_at, active. 상품 필드: product_id, brand_id, category, variant_id, option_label, image_url, image_status, rights_reference, merchant_id, destination_region, currency, checked_at, availability_status. 후보 스냅샷은 공개 당시 버전으로 보관한다.

올리브영 Top30 후보 사용은 사용자 요구다. 카테고리·국가·순위 기준·확인일·원본 근거와 실제 SKU/옵션 일치가 검증되기 전 'Top30' 표시를 하지 않는다. Stylevana 판매 여부·이미지 사용 조건도 별도 확인한다. 인기 순위와 제휴 판매 가능 여부는 서로 다른 속성이다. 선택이 없는 옵션·이미지·효능을 생성해 채우지 않는다.

## 5. 게임 → 커뮤니티 맥락 전달 계약 (신규)

1. 결과에서 사용자가 자기 이야기를 직접 작성한다. 캐릭터 답과 본인 경험은 분리 저장한다.
2. '서울뷰티에서 이야기하기'를 누르면 서버가 만료 있는 불투명 handoff_id를 발급한다. URL에 고민 원문·피부 정보·개인 메모를 넣지 않는다.
3. 수신 화면은 본인이 선택한 지역을 유지하고 제품·관심 조건으로 대화 후보를 제안한다. 추천 없음이면 전체 탐색/직접 만들기. 방에 자동 입장하지 않는다.
4. 본인 작성 텍스트는 전달 목적·공개 범위를 안내한 뒤 초안으로만 가져온다. 계정 연결이 필요하면 인증 후 원래 맥락으로 복귀한다. 게임 시작 전 로그인은 요구하지 않는다.
5. 글 게시 직전 편집·공개 확인을 받는다. 비공개 저장, 공개 글, 게임 공유는 별도 행동이다. 다시 누르거나 요청을 재시도해도 중복 게시하지 않는다.
6. account_id 연결은 본인이 동의한 이벤트 범위에 한하며 철회·삭제 경로를 제공한다. 익명 기기와 계정 수를 하나의 사람 수로 단정하지 않는다. 연결되지 않은 세션은 미귀속으로 남긴다.

handoff_id 권한·만료·재사용 정책, 계정 병합 동의 UI, 삭제 전파는 구현 전 보안/운영 검토 후 확정한다. 이 요구를 현재 기능으로 표시하지 않는다.

| 판매처 클릭 | click_id, 출발 맥락, 제품·옵션·국가·시각 | 귀속·이동 오류·판매처 성과 | URL에 고민/메모/개인정보 넣지 않음 |
| 주문 원장 | merchant+외부 거래키, clickref, 상태·금액·수수료·통화 | 승인 주문·순수익·환불 대조 | 구매 자가 응답과 별도 |

원시 이벤트와 최신 답변 집계를 분리한다. 수정 전후 답변을 행동 건수로 보관하더라도 캐릭터 선택 분포에서 한 기기의 수정 답을 여러 사람처럼 세지 않는다. 기기 쿠키 삭제·공유 기기·크로스 기기 한계를 명시한다.

데이터의 가치는 '누가 어떤 피부일 것이다'가 아니라 '어떤 가상 상황에서 어떤 기준으로 골랐는지', '본인이 실제로 무엇을 쓰고 어떤 경험을 했는지', '그 뒤 어떤 대화·제품 행동이 있었는지'를 구분해 축적하는 데 있다. 외부 통계 제공은 후속 검토로 두며 표본·기간·동의·최소 집단 크기·편향을 확인하기 전 판매 가능한 데이터 자산이라고 주장하지 않는다.

| 친구 | share_click → invite_visit → friend_start → choice_complete → comparison_view | 링크 방문부터 새 답·공개까지 | friend_events 기존; 화면 이벤트와 중복 합산 금지 |
| 개인 답 | reflection_start, reflection_saved | 입력 시작 / 서버 비공개 저장 성공 | 게임 기존 |
| 서울뷰티 클릭 | community_open | 게임에서 이동 버튼 클릭 | 게임 일부 경로 기존; 도착 아님 |
| 실제 도착 | community_handoff_landed | 대상에서 유효 handoff 수신 | 신규 |
| 글·대화 | community_first_contribution, reply_received, meaningful_reply_marked | 실제 저장된 질문/답변 / 타인 답변 / 질문자의 도움 확인 | 통합 신규; 기존 개별 이벤트와 매핑 필요 |
| 상품 | product_detail_view, product_save, affiliate_link_impression, merchant_click | 식별된 상품/옵션 보기·저장·링크 노출·서버 클릭 | 기존 커뮤니티 정의와 통합 필요 |
| 주문 | order_report_imported, order_status_changed | 제휴 원장 수신·상태 변경 | 통합 신규 |
| 복귀 | room_revisit, journey_return | 실제 재방문·후속 행동 | 통합 코호트 신규 |

일반 BridgeCTA와 Reflection 양쪽 이동에 같은 출발 이벤트가 필요하다. community_open만으로 도착률을 계산하지 않는다. 타임존은 저장 UTC, 보고서 KST/지역 선택을 명시한다. 가시·포커스 상태의 체류시간만 집계하고 유휴·끊긴 세션은 무한 연장하지 않는다.

## 8. 퍼널·코호트·귀속 기준

첫 파일럿 보고창은 유입 후 7일, 구매는 각 제휴사 공식 귀속 창을 따른다. 7일이 지나지 않은 코호트는 완료 비교에서 제외하거나 미성숙으로 표시한다. 아래 비율은 동일 출발 코호트의 순서가 확인된 고유 주체를 분모·분자로 사용한다. 익명/계정 지표는 따로 보고한다.

| 질문 | 분자 / 분모 | 함께 볼 값 |
|---|---|---|
| 어떤 인물이 끌리는가 | 인물별 게임 시작 기기 / 해당 인물 노출 기기 | 노출 위치·기간·유입 채널 |
| 게임이 끝나는가 | 답 저장 기기 / 시작 기기 | 단계 이탈·저장 오류·완료 시간 |
| 친구가 실제 하는가 | 친구 새 답 저장 기기 / 유효 초대 방문 기기 | 공유 클릭·링크 생성은 보조 |
| 비교가 재밌는가 | 비교 확인 기기 / 친구 답 저장 기기 | 같은/다른 선택·다음 게임 |
| 나의 이야기로 이어지는가 | 비공개 실제 답 저장 기기 / 게임 결과 본 기기 | used/looking·건너뛰기 |
| 서울뷰티에 도착하는가 | handoff 도착 기기 / 이동 클릭 기기 | 맥락 유실·인증 이탈 |
| 대화에 참여하는가 | 실제 첫 기여 계정 또는 기기 / handoff 도착 동종 주체 | 읽기만 한 비율·답변 대기 |
| 대화가 도움되는가 | 도움 표시한 질문 / 답변 받은 질문 | 답변 소요·후속 대화 |
| 구매 판단으로 가는가 | 상품 상세→판매처 서버 클릭 주체 / 상품 상세 주체 | 게임 직접 이동·대화·검색 분리 |
| 주문이 귀속되는가 | 귀속 주문 / 유효 판매처 클릭 | 사용자 전환율과 주문 수 비율 분리 |
| 돈이 남는가 | 승인 수수료 합계−취소/반품 조정 | 통화별 순수익·실제 지급액 별도 |
| 다시 오는가 | D1/D7/D30 재방문 주체 / 성숙 첫 참여 코호트 | 방문과 실제 기여 재방문 분리 |

공유받은 친구가 다시 초대할 수 있으므로 invite_id와 상위 유입을 보관하되 한 거래를 여러 초대자에게 중복 수익 귀속하지 않는다. 초기 채널 비교는 최초 유입, 구매 화면 기여는 마지막 내부 source_surface로 병렬 보고하고 최종 주문 귀속은 제휴사 원장을 따른다. 연결 실패는 미귀속으로 남긴다. 이벤트별 고유 기기 수를 단순 나열한 기존 진단은 순차 퍼널이 아니다.

## 9. 구매·수익 상태와 신뢰

상태는 독립적으로 관리한다: 판매처 클릭 → 자가 구매 응답(선택) / 제휴 주문 수신 → pending → approved 또는 declined; 취소·반품·삭제·수수료 조정은 원장 값으로 갱신한다. 보고서의 거래키를 해시해 중복 수신을 방지하고 변경 이력을 남긴다. 원장 매칭 실패·지연을 표시한다. 금액은 최소 화폐 단위 정수, 통화별 합계로 관리하며 환산 수익은 환율·기준일을 명시한다.

“샀어요”는 자가 응답이고 인증 구매가 아니다. 주문 승인과 수수료 지급도 다르다. 추적이 끊긴 주문은 0건이라고 단정하지 않고 미확인으로 표시한다. 실제 외부 주문 보고서를 받기 전 전환·매출을 성공 처리하지 않는다.

## 10. 관리자·운영

운영자는 일별·지역·언어·유입·인물·상황·후보 버전·제품군·브랜드·제품·옵션·추천 이유별로 본다. 각 수치에 표본 수·기간·분모·테스트 제외 여부를 표시한다. 노출이 다른 인물을 총 선택 건수만으로 순위 매기지 않는다. 비교 표본이 작으면 탐색 결과로 표기한다.

패널은 획득/게임/친구/자기 이야기/커뮤니티/상품/주문/재방문/오류로 구분하고, 연결되지 않은 저장소의 수치를 통합 사용자 수로 합치지 않는다. 운영 D1 대시보드와 서울뷰티 관리자 권한은 현재 별도다. 통합 조회는 관리자 인증·최소 권한·감사 기록 후 구현한다. 공개 클라이언트로 개인 답변·주문 원장을 반환하지 않는다.

보존·삭제 정책 제안: 원시 분석 이벤트 90일, 비공개 reflection과 handoff는 최대 30일, handoff 토큰은 24시간 만료. 이는 미설정 제안이며 적용 전 동의·삭제 요청·백업·운영 필요를 검토해 확정한다. 공개 글과 정산 원장은 서비스/법정 보존 요구를 별도 검토한다. 확정 전 이미 자동 삭제 중이라고 고지하지 않는다.

## 12. 실행 순서와 완료 판단

1. P0 콘텐츠·사진·실기기: 두 상황의 설명, 실제 후보/옵션, 단계 수, 공유 왕복 검수. 신규 캐릭터 확대보다 이해·완료 우선.
2. P0 handoff·초안·첫 대화: 맥락 전달/동의/초안 복구/관련 대화·빈 상태/직접 게시. 질문에 답해줄 초기 운영자와 응답 시간 운영 기준 정하기.
3. P0 공통 계측·판매처 서버 클릭: 이벤트 중복 제거·도착 수신·연결 범위·테스트 제외·출발점 귀속. 통합 테스트 한 건을 원장까지 대조.
4. 10~20명 관찰 → 약 100명 누적 실험: 한미를 별도로 보고, 완료보다 실제 이야기·대화 효용·친구 완료를 확인. 목표값은 첫 관찰 후 사전 확정해 다음 실험부터 적용.
5. P1 공식 주문 보고서·환불·승인 수수료, 실제 후기와 재방문. 구매 클릭이 발생해도 귀속 전 수익을 추정 실적으로 표시하지 않음.
6. P2 블러셔·눈 화장·선케어·헤어·가방·연속 사건 확장. 콘텐츠별 목적·후보 충분성·정보 가치 확인 후 배포.

개발 이슈에는 위 J ID, 담당, 의존성, 완료 기준, 확인 환경, 테스트/운영 구분을 함께 적는다. 이번 문서 업데이트는 담당 자동 배정·DB 마이그레이션·전체 기능 완료가 아니다.

## 13. 이번 확정과 후속 결정

확정: 별도 게임 유입 경로 허용, 실제 서울뷰티 도메인, 게임 추천과 실제 경험 분리, 친구 답 후공개, 명화 절반 화면, 복수 이유, 본인 이야기에서 대화 연결, 구매 optional, 한국·미국 병행. 기존 '게임형 온보딩 제외'는 이 별도 경로에 한해 대체되며 본 서비스 로딩 캐릭터 복원 지시는 아니다.

후속 확정: handoff/계정 동의·보존 정책, 운영 담당과 답변 시간, 한국 실판매처 데이터·Top30 근거, 카카오 설정, 제휴사별 귀속 창·리포트 포맷, 실험 기간·목표값. LLM은 필수 아님: 초기 게임·문구·분류·초안은 정해진 규칙으로 구현한다. 실제 경험의 자동 해석·생성 추천은 이 범위에 포함하지 않는다.
