# SeoulBeauty 서비스 기획

기준: 2026-10-19 KST. [전략](STRATEGY.md)을 화면·행동·수용 기준으로 옮긴다. 아래는 목표 경험과 검토 후보이며 전체 구현·출시 완료 명세가 아니다. 개별 구현 상태는 Issue와 PR·검증 증거를 따른다.

## 핵심 사용자 흐름

첫 방문(선택형 피부 타입·고민 설정 또는 건너뛰기) → 비슷한 고민의 채팅방 추천 → 대화 읽기 → 질문·답변·후속 대화 → 연결 상품 확인·공유 → 저장 또는 판매처 이동 → 대화·상품 재방문.

검색·브랜드 탐색으로 들어온 이용자도 상품에서 관련 대화와 경험을 찾을 수 있게 한다. 웹과 iPhone에서 같은 개념·표현을 사용하되 플랫폼별 배치와 실제 동작은 각각 검증한다.

| 화면·영역 | 이용자의 일 | 목표 경험·기획 | 최소 수용 기준 |
|---|---|---|---|
| 첫 방문 온보딩(신규 설계) | 내 피부 타입과 고민에 가까운 대화를 찾기 | 피부 타입 단일 선택 → 피부 고민 복수 선택 → 맞춤 채팅방 추천. 건너뛰기 허용, 선택 정보는 비공개 | 선택·미선택·재방문·언어 전환·저장 실패·추천 결과 없음 상태 확인 |
| 맞춤 채팅방 추천(신규 설계) | 같은 고민의 사용자 경험을 확인하기 | 기존 채팅방의 고민·타입 태그와 활성도를 이용해 추천 근거 표시. 무인 방 자동 생성 금지 | 추천방 입장과 원래 인기 채팅방으로의 폴백, 내 활동에서 선택값 수정 검증 |
| 커뮤니티 홈 | 어디서 무엇을 이야기할지 찾기 | 참여 대화 복귀 아래 맞춤 추천 영역 추가. 기존 활성 대화·언급 상품·최근 질문·전체 주제 보존 | 추천 없는 사용자도 기존 탐색 가능, 빈 화면·로딩·오류·재시도와 대화 이동 검증 |
| 대화·글 | 묻고 답하고 경험 나누기 | 익명 표시와 간단한 작성. 글·댓글과 실시간 채팅의 역할을 구분 | 작성·답변·재방문 시 문맥 유지, 실패 시 입력 손실 방지 |
| 상품 첨부 | 이야기하는 상품을 바로 보여주기 | 대화 중 검색 → 정확한 상품·옵션 선택 → 사진·이름이 있는 카드 | 첨부·열기·취소, 검색 결과 없음·오류, 상품 오연결 방지 |
| 상품 상세 | 어떤 상품인지 이해하고 경험 확인 | 상품 설명·옵션·관련 대화·후기·현재 가격·판매처 | 작성한 분류 설명과 허용된 공식 설명 구분, 미확인 효능 생성 금지, 판매처 이동 |
| 브랜드·검색 | 원하는 상품 찾기 | 공식 로고·브랜드 필터와 검색. 로고 셀 여백·터치 영역 일관성 | 실제 상품 필터, 선택 상태·로딩·실패·빈 결과, 모바일 겹침 없음 |
| 저장·내 활동 | 관심 상품·대화와 내 피부 관심사를 다시 찾기 | 기존 저장·참여 기록 유지, 관심사 수정·초기화 메뉴 추가(별도 프로필 탭 없음) | 변경 이후 추천 갱신, 상품 저장→재방문 유지, 추적 요청 없음, 기기 내 스냅샷의 가격 한계 표시 |
| 참여자 표시 | 경험의 맥락 판단 | 익명 닉네임 중심. 사진형 프로필은 필수로 두지 않는 안을 우선 검토 | 실제 신원 공개를 요구하지 않음. 사용자 구분·대화 연속성은 유지 |

## 검증 후 확정할 기능

- 사진: 발색·사용 경험 설명에 추가 효용이 있는지 확인한다. 기존 사진 관련 구현이 있어도 운영 정책과 실제 검증을 완료한 것으로 보지 않는다.
- 피부 타입·고민: **첫 방문 선택형 온보딩과 채팅방 추천을 기획에 반영했다.** 실제 앱·데이터 저장·추천 알고리즘·동의 흐름은 아직 구현·검증 완료가 아니다. 인종·피부 특성은 사진/아바타나 행동에서 추정하지 않으며, 타인에게 선택값을 자동 공개하지 않는다. 비슷한 조건이 같은 효과를 보장하지 않는다. 피부 톤 세부 정보는 후속 검토한다.
- 언어: 제품명 SeoulBeauty는 고유명으로 유지하되 **한국어와 영어 시스템 문구는 화면 전체에서 분리**한다. 기기 언어 또는 직접 선택한 언어를 일관 적용하고 설정을 보존한다. 사용자가 쓴 채팅 메시지·상품명은 원문 유지, 공식 설명 사용권과 번역은 별도 검토한다. 웹/iPhone의 전체 화면과 오류/빈 결과/접근성을 언어별 검증한다.
- 사진형 프로필·번역 확대·리워드 및 피부 톤·아바타는 이번 기획 정리로 개발 착수하지 않는다. 피부 타입·고민의 **채팅방 추천 개인화**만 신규 설계로 포함하며 실제 출시 상태와 구분한다.


## 관리자 보드의 화면별 고객 여정·구성요소·KPI (2026-10-19 신규 설계)

기존 `/admin` → **서비스 기획** → **화면별 고객 여정 · 구성요소 · KPI**의 인터랙티브 보드에 추가한다. 기존 승인 스크린샷, Community/Search/내 활동의 3탭, 게시글/실시간 채팅, 상품 첨부·브랜드·검색·저장 동작은 대체하지 않는다. 신규 피부 온보딩만 별도 미리보기를 제공하며 한국어/English 텍스트를 구분한다.

| 화면·단계 | 고객 행동 | 유지·추가 구성요소 | 단계 KPI(분모·기준) |
|---|---|---|---|
| 온보딩 1 | 피부 타입 선택 또는 건너뛰기 | 신규: 단일 선택 칩·건너뛰기·언어 표시. 선택값은 비공개 | 피부 타입 선택률 = 선택자 / 해당 단계 노출자, 건너뛰기율 |
| 온보딩 2 | 피부 고민 복수 선택 | 신규: 관심사 칩·선택 확인·뒤로가기 | 완료율 = 완료자 / 시작자, 2단계 이탈률 |
| 온보딩 3 | 추천받은 대화방 선택 | 신규: 기존 채팅방의 고민/피부 타입 태그, 추천 이유, 활성도·대체 추천 | 추천방 입장률 = 입장자 / 추천 노출자 |
| 커뮤니티 홈 | 맞춤 방 또는 활발한 기존 대화 진입 | 추가: 참여한 대화 복귀 다음 맞춤 추천. 기존 인기·상품·질문·주제 섹션 유지 | 추천방 첫 발화율 = 전송자 / 추천방 입장자, 기존 홈 대화 진입률 |
| 채팅방·게시글 | 경험 읽기 → 질문·답변 | 기존 익명 대화·게시글/채팅 구분·상품 첨부 유지, 주제 태그만 강조 | 유용한 답변 비율, 첫 유용한 답변 시간, 후속 발화율 |
| Search/브랜드/상품 | 상품 발견 → 관련 대화 → 첨부·공유 | 기존 브랜드 로고·상품 상세·관련 대화·상품 첨부 흐름 유지 | 상품→대화 진입률, 대화→상품 상세 이동률, 첨부→전송률 |
| 내 활동 | 참여 대화 복귀·관심사 변경 | 기존 참여/저장 유지, 피부 관심사 수정·초기화 추가 | 관심사 변경 후 추천방 진입률, 질문자·답변자 D7 재방문율 |

위 KPI는 **측정 정의·우선순위 제안**이며 실제 이벤트 수신·값·목표치는 미확정이다. 개인 피부 정보는 추천에 필요한 최소 범위에서만 다루고, 프로필에 공개하지 않는 것을 기본값으로 제안한다. 언어별 추천은 동일 주제 코드를 사용하되 사용자가 작성한 대화는 자동 번역하지 않는다. 관리 보드의 미리보기를 실제 소비자 앱 기능으로 오인하지 않는다.

## 신뢰·운영과 데이터

현재 가격의 출처와 확인 시각을 구분하고 배송비·세금·재고 미확인은 확정 총액으로 표현하지 않는다. 제휴 링크임을 고지하고 클릭과 주문·정산을 구분한다. 브랜드 로고는 출처 기록과 사용 권한 확인을 별도 항목으로 관리한다.

상품·후기 사진, 삭제·신고·차단·홍보 관리, 개인정보와 위치 메타데이터 처리 등은 실제 공개 범위에 맞춰 검증한다. 개인 후기는 개인 경험으로 표시하고 검증된 구매 후기처럼 오인시키지 않는다. 상세 구현 기록: [COMMUNITY_COMMERCE](COMMUNITY_COMMERCE.md).

공통 이벤트 후보: 주제 진입, 질문 작성, 답변·후속 대화, 상품 첨부·열기, 저장·재방문, 판매처 클릭, 확인된 주문. 수집 여부와 동의·식별 범위는 실제 구현 및 정책과 대조하며 이 문서만으로 수집 완료를 주장하지 않는다.

## 전략과 기능을 연결하는 예

| 전략 가설 | 기획안 | 확인할 결과 |
|---|---|---|
| 비슷한 조건의 경험이 선택에 도움된다 | 선택 피부 정보와 질문 맥락 표시 | 선택에 도움 응답·후속 질문, 입력 부담 |
| 상품을 다시 찾는 수고가 크다 | 대화 중 상품 검색·카드 첨부 | 정확한 상품 도달·첨부 성공, 대화 흐름 유지 |
| 좋은 답변이 재방문 이유가 된다 | 질문·답변과 참여 기록 복귀 | 답변 확인·후속 대화·질문자와 답변자 재방문 |

개별 기능의 상세 상태·담당·차단·테스트는 #26이 연결하는 기존 Issue를 갱신한다. 같은 기능을 새 Issue로 복제하지 않는다.
