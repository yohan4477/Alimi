# SeoulBeauty 서비스 기획

기준: 2026-10-19 KST. [전략](STRATEGY.md)을 화면·행동·수용 기준으로 옮긴다. 아래는 목표 경험과 검토 후보이며 전체 구현·출시 완료 명세가 아니다. 개별 구현 상태는 Issue와 PR·검증 증거를 따른다.

## 핵심 사용자 흐름

첫 방문(스킨케어·메이크업 **독립 복수 선택** 또는 건너뛰기) → 선택한 분야별 **세부 고민 복수 선택** → 이미 만들어진 사용자 공개 방 중 **고민 교집합·분야·실제 활동을 고려한 추천** → 대화 읽기 → 질문·답변·후속 대화 → 관련 상품 확인·공유 → 판매처 제휴 링크 또는 저장 → 대화·상품 재방문. 피부 타입·톤은 이 과정의 필수 관문이 아니라 선택형 후속 정보다.

검색·브랜드 탐색으로 들어온 이용자도 상품에서 관련 대화와 경험을 찾을 수 있게 한다. 웹과 iPhone에서 같은 개념·표현을 사용하되 플랫폼별 배치와 실제 동작은 각각 검증한다.

## 게임형 픽셀 가이드 온보딩 — 2026-10-19 결정

**첫 방문 UX 표면만 게임처럼 만들고 실제 목적은 같은 고민의 채팅방에서 첫 대화를 시작하는 것**이다. 기존 사용자의 2D 픽셀 한복 소녀(기본 하늘색 한복)를 **80~110px 정도의 작은 안내자**로 사용한다. 큰 배경·몬스터·레벨업·강제 미션은 넣지 않는다.

| 화면 | 캐릭터 역할·짧은 대사 | 실제 조작·동선 | KPI |
|---|---|---|---|
| 1. 인사와 분야 | 손을 흔들며 “어떤 뷰티 이야기가 궁금해?” | Skincare와 Makeup **각각 복수 선택**(둘 다 가능), 미선택·둘러보기 허용 | 첫 방문 이탈, 두 분야 동시 선택, 스킵 후 대화 열람 |
| 2. 분야별 고민 | “요즘 어떤 게 제일 궁금해?” | 선택한 분야의 **고민 복수 선택**, 뒤로가기·건너뛰기; 피부 타입·톤 필수 아님 | 단계 이탈, 선택 완료, 첫 유의미 참여 |
| 3. 대화 발견 | “찾았다! 여기서 이야기하고 있어!” | 기존 **실제 공개 방**의 고민 일치 이유·최근 대화 노출. 방 읽기 / 전체 탐색 / 검색 / **자유롭게 방 만들기**. 입장 후 가이드는 퇴장 | 추천방 입장, 방 열람→첫 메시지, 생성·검색 경로 |
| 채팅 이후 | 가이드는 화면을 가리지 않음 | 기존 Posts / Live Chat / 상품 첨부·공유 / Search / My Activity 유지 | 유용한 답변·D7, 대화→상품 이동 |

**가이드 vs 내 캐릭터는 별개**다. 기본 한복 가이드 1명은 온보딩 P0의 UX 방향으로 채택한다. 제작된 **한복 5종 + 아이돌 패션 영감 5종**은 초기 입력 관문이 아닌 **P1의 선택적 아바타/의상 꾸미기** 후보로 관리한다. 이미지나 의상만으로 피부 타입·성별·나이·인종을 추정하거나 공개하지 않는다. 실제 연예인 협업/공식 의상처럼 표기하지 않는다.

**검증:** 캐릭터 있음/없음 A/B(같은 화면·같은 추천 로직), 다른 축으로 온보딩 먼저/둘러보기 먼저를 실험한다. 온보딩 완료율만 올리고 첫 실제 발화율이 낮아지면 성공이 아니다. 한국어/영어 대사 완전 분리, 접근성·축소 애니메이션·320/390/1024px·딥링크 비차단을 확인한다. 자세한 카피·수용 조건·의상 자산 상태는 [픽셀 가이드 온보딩 명세](PIXEL_GUIDE_ONBOARDING.md) 참조.

**상태:** 관리자 기획·디자인 시안 범위다. **웹/iPhone 앱 코드·이미지 자산 게시·사용자 실험·배포는 이번 문서 변경으로 완료되지 않는다.**

## 네트워크 로딩의 캐릭터 동반자 · 10종 의상 순환

온보딩과 구분해 **커뮤니티 홈·채팅 기록·글/댓글·상품 및 브랜드 데이터**의 실제 비동기 대기 시 작은 픽셀 캐릭터가 등장하도록 웹/iOS 컴포넌트를 추가했다. 0~400ms는 기존 기본 로딩만 유지하고, 그 이후 2.2초 간격으로 **한복 5종 + 패션 의상 5종**을 반복한다. 캐릭터 때문에 데이터 표시를 기다리지 않고, 오류는 재시도·원래 탐색을 남긴다. 네트워크 요청당 이미지 10장을 내려받지 않도록 4.8KB 경량 스프라이트 1장을 쓴다. 화면읽기 사용자를 위해 안내 문구만 읽고 픽셀 캐릭터는 장식 처리한다. Reduce Motion에서 순환 정지. [전체 스펙](PIXEL_GUIDE_ONBOARDING.md).

**핵심 KPI와 가드레일:** 실제 데이터 응답시간 p50/p95, 로딩 중 이탈/재시도, 방 입장→첫 유효 발화, D7. 로딩 노출을 높이는 것이 목표가 아니다. **현재 코드는 웹/iOS 파일에 반영했지만 실기기·운영 배포 검증은 아직 별도**이며 캐릭터가 안내하는 첫 방문 온보딩 자체는 기획 시안 단계다. 공연 의상은 실제 아이돌 공식 협업처럼 표시하지 않는다.

## 검증 후 확정할 기능

- 사진: 발색·사용 경험 설명에 추가 효용이 있는지 확인한다. 기존 사진 관련 구현이 있어도 운영 정책과 실제 검증을 완료한 것으로 보지 않는다.
- 관심 분야·고민: **스킨케어/메이크업을 상호 배타적 분류가 아닌 복수 선택 가능한 관심 분야로 확정**한다. 각 분야의 세부 고민도 복수 선택; 추천은 두 분야의 선택값을 함께 사용한다. 분야를 끄면 그 분야의 숨겨진 고민이 추천에 남지 않도록 처리한다. 피부 타입·톤은 선택형 추가 정보다. 실제 소비자 앱·데이터 저장·추천 알고리즘·동의 흐름은 아직 구현·검증 완료가 아니다. 인종·피부·연령·성별을 사진/아바타로 추정하지 않으며, 선택값은 비공개를 기본으로 한다.
- 언어: 제품명 SeoulBeauty는 고유명으로 유지하되 **한국어와 영어 시스템 문구는 화면 전체에서 분리**한다. 기기 언어 또는 직접 선택한 언어를 일관 적용하고 설정을 보존한다. 사용자가 쓴 채팅 메시지·상품명은 원문 유지, 공식 설명 사용권과 번역은 별도 검토한다. 웹/iPhone의 전체 화면과 오류/빈 결과/접근성을 언어별 검증한다.
- 사진형 프로필·번역 확대·리워드 및 피부 톤·사용자 아바타 편집은 이번 기획 정리로 개발 착수하지 않는다. **픽셀 한복 가이드는 온보딩에만 사용하는 P0 UX 설계**, 의상 10종의 프로필 꾸미기는 P1 검증 후 선택 기능이다. 실제 출시 상태와 구분한다.


## 관리자 보드의 화면별 고객 여정·구성요소·KPI (2026-10-19 신규 설계)

기존 `/admin` → **서비스 기획** → **화면별 고객 여정 · 구성요소 · KPI**의 인터랙티브 보드에 추가한다. 기존 승인 스크린샷, Community/Search/내 활동의 3탭, 게시글/실시간 채팅, 상품 첨부·브랜드·검색·저장 동작은 대체하지 않는다. 신규 **관심 분야 복수 선택 → 분야별 고민 복수 선택 → 추천방** 온보딩만 별도 미리보기로 제공하며 한국어/English 텍스트를 구분한다.

| 화면·단계 | 고객 행동 | 유지·추가 구성요소 | 단계 KPI(분모·기준) |
|---|---|---|---|
| 온보딩 1 | Skincare / Makeup 중 **둘 다·한쪽·미선택** | 신규: 분야별 선택 토글(복수 선택), 건너뛰기·언어 전환, 선택 취소. 피부 타입은 초기 필수 설문 제외 | 관심 분야 복수 선택률 = 둘 다 선택자 / 관심사 선택 시작자, 선택 분포(스킨만/메이크업만/둘 다/미선택), 스킵률 |
| 온보딩 2 | 선택한 분야의 세부 고민을 각각 복수 선택 | 신규: 분야별 그룹(스킨케어: 트러블·민감성·건조 등 / 메이크업: 쿠션 호수·틴트·지속력 등), 독립 다중 선택·뒤로가기·건너뛰기 | 고민 선택 완료율 = 고민 1개 이상 선택한 이용자 / 고민 단계 노출자, 두 분야 교차 선택 비율, 단계별 이탈률 |
| 온보딩 3 | 두 분야·세부 고민을 반영해 방 찾기 | 새로 생성된 방을 포함해 현재 공개된 방에서 고민 일치 기준 추천. 자유 탐색·검색·**방 만들기** 병렬 진입. 추천 결과 없으면 전체 인기 주제·방 생성 경로 표시 | 추천방 입장률, 추천 외 방 탐색·생성 비율, 첫 발화율·D7 |
| 커뮤니티 홈 | 추천·전체 탐색·방 생성 중 자유 선택 | 기존 참여 대화·인기 상품·질문은 유지. 고민별 추천 외에 전체 공개 방 목록/검색과 **방 만들기**를 항상 제공 | 추천/검색/직접 생성의 방 진입 비율, 첫 참여·D7 |
| 채팅방·게시글 | 경험 읽기 → 질문·답변 | 기존 익명 대화·게시글/채팅 구분·상품 첨부 유지, 주제 태그만 강조 | 유용한 답변 비율, 첫 유용한 답변 시간, 후속 발화율 |
| Search/브랜드/상품 | 상품 발견 → 관련 대화 → 첨부·공유 | 기존 브랜드 로고·상품 상세·관련 대화·상품 첨부 흐름 유지 | 상품→대화 진입률, 대화→상품 상세 이동률, 첨부→전송률 |
| 내 활동 | 참여 대화 복귀·스킨케어/메이크업/고민 변경 | 기존 참여/저장 유지, 두 분야와 고민 재선택·초기화 추가 | 변경 후 추천방 입장률, 질문자·답변자 D7, 선택 조합별 D7 |

위 KPI는 **측정 정의·우선순위 제안**이며 실제 이벤트 수신·값·목표치는 미확정이다. 개인 피부 정보는 추천에 필요한 최소 범위에서만 다루고, 프로필에 공개하지 않는 것을 기본값으로 제안한다. 언어별 추천은 동일 주제 코드를 사용하되 사용자가 작성한 대화는 자동 번역하지 않는다. 관리 보드의 미리보기를 실제 소비자 앱 기능으로 오인하지 않는다.

## 관심 분야 조합 및 추천 설계 수용 조건 (신규)
 
**선택 모델:** `interests = { skincare: boolean, makeup: boolean }`과 `concerns = string[]`(각 고민은 변하지 않는 고유 ID와 분야 정보를 갖는다). 언어는 같은 ID의 레이블만 번역한다. 피부 타입은 별도의 선택 정보로 보관하며 관심 분야를 대체하지 않는다.

**추천 우선순위:** 기존 채팅방에서 선택한 세부 고민과 일치하는 실제 대화를 우선 추천한다. 피부와 메이크업을 모두 선택했으면 두 분야의 추천 후보와 두 분야에 걸친 주제 후보를 함께 고려하고, 실제 최근 발화·답변 가능성을 함께 사용한다. **임의 가중치(과거 '고민 60%·타입 30%·활성 10%' 등)를 확정된 알고리즘처럼 기재하지 않는다.** 추천과 일치하는 기존 방이 없으면 전체 방 탐색·검색·**사용자 자유 방 생성**을 제공한다. 추천 시스템은 가짜 방·활동을 만들어내지 않으며 새로 만들어진 방도 탐색에서 접근 가능해야 한다.

| 선택 상태 | 기획 동작 | 허용/예외 검증 |
|---|---|---|
| Skincare만 | 스킨케어 세부 고민 칩과 그에 맞는 대화 추천 | 메이크업 태그가 결과를 오염시키지 않음 |
| Makeup만 | 메이크업 세부 고민 칩과 그에 맞는 대화 추천 | 피부 타입·스킨케어 고민 입력 강제 없음 |
| **둘 다** | 두 분야 고민을 모두 표시하고 복수 선택, 공통/분야별 방 추천 | 한 사람의 교차 고민을 배타적으로 분리하지 않음 |
| 둘 다 미선택/건너뛰기 | 인기/최근 공개 대화·전체 탐색·방 만들기 모두 가능 | 관심사·피부 정보 선택을 방 생성 조건으로 두지 않음 |
| 분야 선택 해제·재선택 | 해당 분야 고민은 추천 후보에서 제외; 재선택/편집 후 다시 적용 | 미표시 세부 고민이 숨은 추천 인자로 남지 않음 |
| 언어 KO ↔ EN | 선택 ID와 단계는 유지, 시스템 문구만 변경 | 선택이 지워지거나 다른 고민으로 매핑되지 않음 |

**성과 측정:** 코호트를 '스킨케어만 / 메이크업만 / 둘 다 / 미선택'으로 분리해 선택 완료·추천방 노출→입장·첫 유의미 발화·D7·대화→제품 상세·제휴 링크 클릭을 본다. 최종 수익은 [전략](STRATEGY.md)의 승인·귀속된 순수수료에 따르며 클릭을 매출로 보고하지 않는다. 소수 집단은 개인식별이 가능한 행으로 공개하지 않는다.

**현재 상태:** 관리자 보드의 시안·고객 여정 명세이며 실제 소비자 앱용 온보딩, 동적 채팅방 추천, 자유 방 생성 UX·악용 방어, 고객 추천 데이터 저장·동의·분석 이벤트·출시는 별도 개발·검증 과제다.

## 방 생성의 자유와 고민별 추천의 분리

**방 생성은 누구에게나 열려 있다.** 사용자는 추천이나 가입 설문과 관계없이 원하는 주제로 공개 방을 만들 수 있다. 제목·설명·선택형 분야/고민 태그만 제안하고, 추천된 목록에 있는 주제만 허용하지 않는다. 스팸·신고·불법 콘텐츠 등 운영 안전장치는 별도로 둔다. 초대를 통한 신규 참여도 지원한다.

**추천은 기존에 실제로 존재하는 방을 찾기 위한 기능이다.** 사용자 생성 방의 주제·고민 태그와 실제 대화·활동을 기반으로 매칭하고, 최근 신규 생성 방에도 탐색 노출 기회를 제공한다. 맞는 방이 없으면 전체 방 목록·검색·방 만들기를 안내한다. 추천 엔진이 자동으로 방을 생성하거나 가짜 채팅을 채우지 않는다.

## 퍼널·화면 이용행동 설계 및 전략 협의

[고객 여정·이용행동·KPI 협의안](FUNNEL_KPI_REVIEW.md)에 세부 단계와 분모를 기록한다. 서비스는 하나의 강제 직선 퍼널이 아니라 ① 고민/관심사 선택→추천 또는 전체 탐색→대화→상품→구매, ② 브랜드/상품 검색→상품 상세→대화 또는 바로 구매, ③ **자유 방 생성→초대→타인 참여→후속 대화**, ④ 기존 대화 복귀라는 연결된 분기를 가진다.

기획 측 제안 지표: 방문 유입 채널·첫 방문 이탈; 관심사 선택/건너뛰기와 단계별 이탈; 추천·검색·공유·생성별 방 진입; 방별 체류시간(실제 화면 표시 시간의 중위값/분위값)과 메시지·유용한 답변; 방 만들기 시작/완료·생성 뒤 타인 참여; 대화→제품 상세→제휴 클릭; 귀속 구매·확정 순제휴수익; 신규/기존 코호트 D1/D7/D30.

**전략 측 협의가 필요한 항목:** 승인 순제휴 수수료 매출 최상위 KPI 유지, 각 퍼널 보조 KPI의 우선순위, 측정 기간·세션 기준·목표치, 사용자 정보 최소 수집·제휴 귀속 방식, 방 생성 운영 가드레일. **아직 실제 전략팀 협의·성과 검증·목표치 승인으로 보고하지 않는다.**

## 신뢰·운영과 데이터

현재 가격의 출처와 확인 시각을 구분하고 배송비·세금·재고 미확인은 확정 총액으로 표현하지 않는다. 제휴 링크임을 고지하고 클릭과 주문·정산을 구분한다. 브랜드 로고는 출처 기록과 사용 권한 확인을 별도 항목으로 관리한다.

상품·후기 사진, 삭제·신고·차단·홍보 관리, 개인정보와 위치 메타데이터 처리 등은 실제 공개 범위에 맞춰 검증한다. 개인 후기는 개인 경험으로 표시하고 검증된 구매 후기처럼 오인시키지 않는다. 상세 구현 기록: [COMMUNITY_COMMERCE](COMMUNITY_COMMERCE.md).

공통 이벤트 후보: 주제 진입, 질문 작성, 답변·후속 대화, 상품 첨부·열기, 저장·재방문, 판매처 클릭, 확인된 주문. 수집 여부와 동의·식별 범위는 실제 구현 및 정책과 대조하며 이 문서만으로 수집 완료를 주장하지 않는다.
