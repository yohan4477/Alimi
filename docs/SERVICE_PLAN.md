# SeoulBeauty 서비스 기획

기준: 2026-10-19 KST. [전략](STRATEGY.md)을 화면·행동·수용 기준으로 옮긴다. 아래는 목표 경험과 검토 후보이며 전체 구현·출시 완료 명세가 아니다. 개별 구현 상태는 Issue와 PR·검증 증거를 따른다.

## 핵심 사용자 흐름

첫 방문(스킨케어·메이크업 **독립 복수 선택** 또는 건너뛰기) → 선택한 분야별 **세부 고민 복수 선택** → 기존 대화방 중 **고민 교집합·분야·실제 활동을 고려한 추천** → 대화 읽기 → 질문·답변·후속 대화 → 관련 상품 확인·공유 → 판매처 제휴 링크 또는 저장 → 대화·상품 재방문. 피부 타입·톤은 이 과정의 필수 관문이 아니라 선택형 후속 정보다.

검색·브랜드 탐색으로 들어온 이용자도 상품에서 관련 대화와 경험을 찾을 수 있게 한다. 웹과 iPhone에서 같은 개념·표현을 사용하되 플랫폼별 배치와 실제 동작은 각각 검증한다.

|---|---|---|---|
| 첫 방문 온보딩(신규 설계) | 스킨케어와 메이크업 관심을 동시에 밝히거나 바로 둘러보기 | ① Skincare/Makeup **각각 ON/OFF 복수 선택** ② 켠 분야의 고민 칩을 분야별로 묶어 **다중 선택** ③ 추천방 미리보기. 둘 다 선택·한 가지만 선택·아무것도 선택하지 않고 건너뛰기 허용 | 전 조합의 선택·해제·뒤로가기·언어 변경·스킵·관심사 수정. 피부 타입 입력이나 로그인 강제하지 않음 |

## 검증 후 확정할 기능

- 사진: 발색·사용 경험 설명에 추가 효용이 있는지 확인한다. 기존 사진 관련 구현이 있어도 운영 정책과 실제 검증을 완료한 것으로 보지 않는다.
- 관심 분야·고민: **스킨케어/메이크업을 상호 배타적 분류가 아닌 복수 선택 가능한 관심 분야로 확정**한다. 각 분야의 세부 고민도 복수 선택; 추천은 두 분야의 선택값을 함께 사용한다. 분야를 끄면 그 분야의 숨겨진 고민이 추천에 남지 않도록 처리한다. 피부 타입·톤은 선택형 추가 정보다. 실제 소비자 앱·데이터 저장·추천 알고리즘·동의 흐름은 아직 구현·검증 완료가 아니다. 인종·피부·연령·성별을 사진/아바타로 추정하지 않으며, 선택값은 비공개를 기본으로 한다.
- 언어: 제품명 SeoulBeauty는 고유명으로 유지하되 **한국어와 영어 시스템 문구는 화면 전체에서 분리**한다. 기기 언어 또는 직접 선택한 언어를 일관 적용하고 설정을 보존한다. 사용자가 쓴 채팅 메시지·상품명은 원문 유지, 공식 설명 사용권과 번역은 별도 검토한다. 웹/iPhone의 전체 화면과 오류/빈 결과/접근성을 언어별 검증한다.
- 사진형 프로필·번역 확대·리워드 및 피부 톤·아바타는 이번 기획 정리로 개발 착수하지 않는다. **두 관심 분야·복수 고민 기반 채팅방 추천**만 신규 설계에 포함하고 실제 출시 상태와 구분한다.


## 관리자 보드의 화면별 고객 여정·구성요소·KPI (2026-10-19 신규 설계)

기존 `/admin` → **서비스 기획** → **화면별 고객 여정 · 구성요소 · KPI**의 인터랙티브 보드에 추가한다. 기존 승인 스크린샷, Community/Search/내 활동의 3탭, 게시글/실시간 채팅, 상품 첨부·브랜드·검색·저장 동작은 대체하지 않는다. 신규 **관심 분야 복수 선택 → 분야별 고민 복수 선택 → 추천방** 온보딩만 별도 미리보기로 제공하며 한국어/English 텍스트를 구분한다.

| 화면·단계 | 고객 행동 | 유지·추가 구성요소 | 단계 KPI(분모·기준) |
|---|---|---|---|
| 온보딩 1 | Skincare / Makeup 중 **둘 다·한쪽·미선택** | 신규: 분야별 선택 토글(복수 선택), 건너뛰기·언어 전환, 선택 취소. 피부 타입은 초기 필수 설문 제외 | 관심 분야 복수 선택률 = 둘 다 선택자 / 관심사 선택 시작자, 선택 분포(스킨만/메이크업만/둘 다/미선택), 스킵률 |

| 커뮤니티 홈 | 맞춤 방 또는 활발한 기존 대화 진입 | 추가: 참여한 대화 복귀 다음 맞춤 추천. 기존 인기·상품·질문·주제 섹션 유지 | 추천방 첫 발화율 = 전송자 / 추천방 입장자, 기존 홈 대화 진입률 |
| 채팅방·게시글 | 경험 읽기 → 질문·답변 | 기존 익명 대화·게시글/채팅 구분·상품 첨부 유지, 주제 태그만 강조 | 유용한 답변 비율, 첫 유용한 답변 시간, 후속 발화율 |

| 내 활동 | 참여 대화 복귀·스킨케어/메이크업/고민 변경 | 기존 참여/저장 유지, 두 분야와 고민 재선택·초기화 추가 | 변경 후 추천방 입장률, 질문자·답변자 D7, 선택 조합별 D7 |

위 KPI는 **측정 정의·우선순위 제안**이며 실제 이벤트 수신·값·목표치는 미확정이다. 개인 피부 정보는 추천에 필요한 최소 범위에서만 다루고, 프로필에 공개하지 않는 것을 기본값으로 제안한다. 언어별 추천은 동일 주제 코드를 사용하되 사용자가 작성한 대화는 자동 번역하지 않는다. 관리 보드의 미리보기를 실제 소비자 앱 기능으로 오인하지 않는다.

## 관심 분야 조합 및 추천 설계 수용 조건 (신규)
 
**선택 모델:** `interests = { skincare: boolean, makeup: boolean }`과 `concerns = string[]`(각 고민은 변하지 않는 고유 ID와 분야 정보를 갖는다). 언어는 같은 ID의 레이블만 번역한다. 피부 타입은 별도의 선택 정보로 보관하며 관심 분야를 대체하지 않는다.

**추천 우선순위:** 기존 채팅방에서 선택한 세부 고민과 일치하는 실제 대화를 우선 추천한다. 피부와 메이크업을 모두 선택했으면 두 분야의 추천 후보와 두 분야에 걸친 주제 후보를 함께 고려하고, 실제 최근 발화·답변 가능성을 함께 사용한다. **임의 가중치(과거 '고민 60%·타입 30%·활성 10%' 등)를 확정된 알고리즘처럼 기재하지 않는다.** 추천할 활성 방이 없으면 인기 K-뷰티 대화와 검색으로 안내하고 빈 방을 생성하거나 활동을 꾸며내지 않는다.

| 선택 상태 | 기획 동작 | 허용/예외 검증 |
|---|---|---|
| Skincare만 | 스킨케어 세부 고민 칩과 그에 맞는 대화 추천 | 메이크업 태그가 결과를 오염시키지 않음 |
| Makeup만 | 메이크업 세부 고민 칩과 그에 맞는 대화 추천 | 피부 타입·스킨케어 고민 입력 강제 없음 |
| **둘 다** | 두 분야 고민을 모두 표시하고 복수 선택, 공통/분야별 방 추천 | 한 사람의 교차 고민을 배타적으로 분리하지 않음 |
| 둘 다 미선택/건너뛰기 | 기본 인기/최근 K-뷰티 대화로 바로 진입 | 가입·피부 정보 입력 없이 둘러보기 가능 |
| 분야 선택 해제·재선택 | 해당 분야 고민은 추천 후보에서 제외; 재선택/편집 후 다시 적용 | 미표시 세부 고민이 숨은 추천 인자로 남지 않음 |
| 언어 KO ↔ EN | 선택 ID와 단계는 유지, 시스템 문구만 변경 | 선택이 지워지거나 다른 고민으로 매핑되지 않음 |

**성과 측정:** 코호트를 '스킨케어만 / 메이크업만 / 둘 다 / 미선택'으로 분리해 선택 완료·추천방 노출→입장·첫 유의미 발화·D7·대화→제품 상세·제휴 링크 클릭을 본다. 최종 수익은 [전략](STRATEGY.md)의 승인·귀속된 순수수료에 따르며 클릭을 매출로 보고하지 않는다. 소수 집단은 개인식별이 가능한 행으로 공개하지 않는다.

**현재 상태:** 관리자 보드의 시안·고객 여정 명세이며 실제 소비자 앱용 온보딩, 백엔드 추천 엔진, 고객 추천 데이터 저장·동의·분석 이벤트·출시는 별도 개발·검증 과제다.

## 신뢰·운영과 데이터

현재 가격의 출처와 확인 시각을 구분하고 배송비·세금·재고 미확인은 확정 총액으로 표현하지 않는다. 제휴 링크임을 고지하고 클릭과 주문·정산을 구분한다. 브랜드 로고는 출처 기록과 사용 권한 확인을 별도 항목으로 관리한다.

상품·후기 사진, 삭제·신고·차단·홍보 관리, 개인정보와 위치 메타데이터 처리 등은 실제 공개 범위에 맞춰 검증한다. 개인 후기는 개인 경험으로 표시하고 검증된 구매 후기처럼 오인시키지 않는다. 상세 구현 기록: [COMMUNITY_COMMERCE](COMMUNITY_COMMERCE.md).

공통 이벤트 후보: 주제 진입, 질문 작성, 답변·후속 대화, 상품 첨부·열기, 저장·재방문, 판매처 클릭, 확인된 주문. 수집 여부와 동의·식별 범위는 실제 구현 및 정책과 대조하며 이 문서만으로 수집 완료를 주장하지 않는다.
