## 현재 관찰된 증거와 한계
- main의 `dist/chat.js`는 게시 중 버튼 비활성화만 하며 서버 idempotency 계약은 존재하지 않는다. 이번 브랜치에서 게임 handoff 게시의 **불명확한 응답 후 재전송을 막는 임시 보호 로직**을 추가했다. 서버 저장에 정확히 한 건만 존재한다는 보장은 아직 없다.
- `docs/BEAUTY_BACKEND_POLICY.md`는 운영 D1 유지 및 Supabase 전환 게이트를 요구한다. 전환·D1 삭제 금지.
- `docs/validation/beauty-launch-completion-2026-10-23.md`의 계정 초안·정산 기능에는 실제 운영 DB 권한과 마이그레이션·실사용 검증 선행 조건이 있다.
- 이번 변경은 실제 계정 연결/운영 DB/공개 게시/주문/배포를 실행하지 않았다.

## 릴리스 차단 게이트
1. 서버 게시 멱등성: 동일 operation_id 동시 요청 10개/응답 유실 → 동일 결과 ID 한 건. 검증 실패 시 운영 공개 게시 확장 차단.
2. DB cutover: 완전한 원본 export·해시 대조·기존 초대 호환·한 writer 유지·롤백 중 데이터 무손실 확인 전 백엔드 스위치 금지.
3. 계정 개인정보: A→B 교차 계정, 로그아웃 직후 비공개 데이터 UI/API 0건. 반례가 있으면 연결 기능 차단.
4. 공유 해금: 취소 또는 링크 미생성 시 완료 이벤트와 해금 없음.
5. 제휴 정산: 실제 광고주 원장과 승인·환불·반전 상태 대조 전 매출을 실적으로 표시하지 않음.
6. KO/EN: UX 문자열 전 화면 검사, 실패·빈 상태·재시도·관리자 링크·동적 메시지 포함.
