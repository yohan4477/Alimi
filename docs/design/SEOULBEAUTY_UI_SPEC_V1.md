# SeoulBeauty UI/UX 상세 명세 v1.0 — 개발 기준안

상태: **기획/디자인 명세 완료, 실제 구현/운영 검증 별도**. 2026-10-22.
기준: 브랜드 v0.3 **Beauty is personal. Let’s talk.** / 경쟁가설 v0.4 **From conversations to living experiences.** / CX 01~06 / PRD 01~08.
원본 디자인 참고: `SeoulBeauty_사용자여정_기획마스터_v07_재방문.pptx` (Google Drive) — 시각적 영감이며 허위 화면/탭/수치 등은 그대로 복사하지 않음.
기준 코드: `dist/index.html`, `dist/chat.js`, `dist/style.css`. Figma 사용하지 않음. 화면의 기준 원본은 실제 구현과 이 명세의 차이 기록.

## A. 브랜드·경쟁 가설
- 사용자는 뷰티 관심사, 고민, 취향을 **자유롭게** 이야기할 수 있다. 사용 후기/피부 정보/구매/회원가입은 기본 대화의 선행 조건이 아니다.
- 나와 관련 있는 맥락을 가진 경험을 찾고, **원본 경험자에게 직접 후속 질문**하며, 상황 변화·후속 결과를 자발적으로 공유할 수 있다.
- 실사용자·자기신고·구매 인증·운영자·협찬을 혼동하지 않는다.
- 유사한 조건이 곧 같은 결과/원인·효능 보장을 뜻하지 않는다. 브랜드 약속과 실제 경쟁력은 구분한다.

## C. 공통 레이아웃/스타일
- 기존 로고 원본 `dist/assets/seoul-beauty-logo.webp` 사용, 임의 텍스트/가짜 로고로 치환하지 않음.
- 색상·폰트는 현재 CSS를 원천으로 사용: `--blue:#0786ff`, `--ink:#222`, `--muted:#92969b`, `--line:#eceef0`; 모바일 시스템 폰트 스택과 현 스타일 보존.
- 커뮤니티 홈 상단 3탭 **추천 / 대화방 / 발견** (`HOME_TABS=['rec','rooms','discover']`).
- 앱 공통 하단 3탭 **커뮤니티 / 탐색 / 내 활동** (`#tabbar`). 알림/후기/마이 등의 새 하단 탭 금지.
- 주제별/제품별은 ‘대화방’ 내부 분류, 전체 메인 탭 아님.
- 주제별 방에는 주제 아이콘, 제품별 방에는 검증된 정확한 제품 사진(없으면 기본 아이콘), 브랜드에는 권리 확인된 로고.
- 미국/한국 지역·언어·판매처 구분. 모바일 390×844 및 작은 폭 320px 기준 줄바꿈/터치 영역 점검.
- 이미지 PPT는 설명 시안; 실제 화면 증거는 운영 웹/iPhone 원본 캡처만 사용.

## D. 상세 상호작용 명세
### UI-01 커뮤니티 홈
기본 커뮤니티 홈에서 가입/설문 없이 실제 대화 목록 열람. 첫 방문 안내는 최대 2줄. 추천은 최근 대화·실제 참여 방·관련 관심사 기반이며 인기/후기 수치 임의 생성 금지. 대화 목록에 질문 제목, 실제 최근 메시지 한 줄, 확인된 고민 태그. 첫 진입에서는 한정된 선택지만 보여주고 나머지는 더보기. 게시물이 없으면 빈 상태와 질문/대화방 만들기 경로 제공. 관심사 변경은 선택.

### UI-02 대화 탐색
대화방 탭에서 주제별·제품별 목록을 명확히 분리하되 필터를 의무 입력으로 만들지 않음. 제목/제품명 검색, 상태(검색중/결과없음/실패), 결과를 터치하면 정확한 대화방 열기. 제품 후보가 유사하면 브랜드·품목·옵션으로 확인.

### UI-03 채팅방
입장 즉시 기존 메시지 표시. 질문/답변/공감/취향 공유 모두 허용하며 후기 유도 자동 팝업 금지. 메시지에 답장할 경우 원본 메시지 ID를 참조. 입력창의 + 메뉴에서 사진·제품·경험 선택; 경험은 **선택적**. 서버로 전송 실패 시 초안 유지, 재시도 중복 방지. 읽기는 로그인 불필요; 익명 작성/닉네임 허용. 차단·신고·삭제 권한은 서버 검증.

### UI-04 경험 공유
전송 전에 ‘사용해 봤는지’, ‘얼마나/몇 번’, ‘어땠는지’의 최소 정보로 시작. 피부·환경·선크림·사용법·문제 해결·사진 등 세부 항목은 상황에 따라 선택. 주제별 방에서는 제품 없이도 가능. 제품별 방에서는 확인된 SKU/옵션 재사용. 작성 취소 시 별도 경험 원본 생성 금지. 실제 전송 때만 독립 원본을 만들고 메시지에 연결; 트랜잭션/멱등성 검증 필요. 이미 작성한 경험은 참조로 재공유.

### UI-05 맥락 있는 경험 발견
‘나와 비슷한 조건’은 강제 회원 프로필이나 임의 유사성 점수가 아니라 **사용자가 선택한 고민/조건과 일치하는 경험 필터**로 시작. 조건 필터는 선택적이며 왜 결과가 나왔는지 표시. 경험이 0개면 ‘조건에 맞는 경험 없음’과 전체 대화 보기. 공개되지 않은 조건을 추정하지 않음. 긍정·부정·혼합된 경험을 나란히 허용. 경험 카드에서 원본 대화로 이동하고 경험자에게 직접 답글 작성.

### UI-06 제품 상세
정보 순서 **제품 기본정보 → 관련 대화/공개 경험 → 판매처**. 제품별 옵션 확인. 실제 경험/자기신고와 광고/협찬을 구분. 가짜 평균 평점·리뷰 수·가격·효능 사용 금지. 별도 가격 추적, 이력, 목표가, 가격 알림 및 불필요한 비교 페이지 없음.

### UI-07 지속되는 경험
대화 중 후속 질문이 새 맥락 정보를 만들 수 있도록 원본 경험 참조. 최초 기록과 이후 결과는 시간 순 연결하되 매주 업데이트 강제 금지. 한 번의 선택적 업데이트로 ‘무엇을 바꿨는지/어떤 변화가 있었는지/언제’ 기록. 관찰 기록은 인과관계 입증 아님. 작성자는 후속 질문에 답하지 않을 권리가 있고 알림을 끄거나 제어할 수 있음. 구현은 파일럿 이후 단계적 도입.

### UI-08 내 활동·알림
내 질문/경험에 직접 달린 답글과 후속 질문 우선. 기존 알림 경로에서 접근, 독립 하단 탭 없음. 정확한 메시지 위치 딥링크, 타깃 삭제/비공개시 안전한 대체 상태. 과도한 알림 묶음, 설정에서 후속 질문 알림 제어. 푸시/시간 임계값 미확정, 초기에는 앱 내 알림 우선.

### UI-09 첫 참여
콘텐츠 읽기와 첫 질문 전에 회원가입·피부 프로필·나이·사용 후기 의무 없음. 첫 작성 시 익명 닉네임 사용. 계정 연동은 기록 보존 필요할 때 선택 안내, 병합은 본인확인/명시적 동의 필요. 기기 세션 유실 기록 복구는 보장하지 않음.

## E. 상태별 QA와 수용 기준
1. 기존 로고 원본, 커뮤니티 상단 3탭, 공통 하단 3탭 유지.
2. 읽기→익명 자유 작성→답장 정상, 경험 공유 없이 사용 가능.
3. 미사용자 질문과 사용자의 자기신고 경험 구분.
4. 메시지/경험 원본 관계 보존, 수정·삭제·숨김 모든 참조 반영.
5. 조건 필터 미일치시 사용자에게 사실대로 표시, 유사성·효과 과장 금지.
6. 직접 답변 알림, 응답 자율성/알림 끄기, 타깃 정확한 딥링크.
7. 합성 데모 데이터·실제 사용자 데이터·운영자 질문 구분.
8. 지역/언어 및 320px 모바일에서 조작, 이동, 뒤로가기/스크롤 검증.
9. 장애 상태/서버 실패/중복 전송/권한 없는 접근 처리.
10. PRD 06 지표(유용한 답변 도달률, 관련 경험 발견, 후속 질문, 이후 결과 기록 등) 실측 검증 — 구현 전 실측 주장 금지.

## F. 구현 순서 및 안전 게이트
- **P0:** 기존 웹 UI 캡처·실제 코드 및 운영 DB 감사 → UI-01~03 기존 구성 보존 개선 → UI-04~05 데이터 원본/트랜잭션/권한 구현.
- **P1:** UI-06~08 맥락 필터·직접 후속 질문·내 활동/알림. 경험 타임라인 실험.
- **P2:** 선택형 후속 결과 갱신, 조건 탐색 고도화, 푸시.
- 실제 배포 전 브랜치 별도·PR 리뷰·iPhone 동작·DB RLS/RPC·가짜 콘텐츠 비노출 검증.

## G. 경쟁 차별화 실험
동일 뷰티 고민에서 ChatGPT/Reddit/현재 리뷰와 서울뷰티를 비교: 관련 경험 발견 시간·유용성, 경험자 직접 후속 질문의 추가 가치, 이후 판단/행동 변화, 답변자 재참여. 결과 미확인 상태에서는 ‘경쟁 우위’라 표현하지 않음.
