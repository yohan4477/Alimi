# 대화방 · 주제 태그 운영 (2026-10-19)

## 구현
- 방은 제목 3–40자, 소개 120자 이내. 태그 없이 생성할 수 있다. 기기당 최근 24시간 3개, 전체 최근 1시간 30개 제한은 삭제 후에도 유지한다.
- 방 만들기에서 19개 주제 태그를 피부 고민 / 메이크업 고민 / 제품·부위로 묶는다. 대표 태그 + 더 보기, 최대 3개. 여드름·트러블과 베이스·쿠션은 각각 통합한다. 기존 온보딩 저장값과 화면 구성은 유지한다.
- 다른 사람의 참여 이력이 없는 방만 개설자가 삭제 가능. 참여 후 나가더라도 삭제 가능 상태로 되돌아가지 않는다. 서버가 동시 참여와 삭제를 같은 방 잠금으로 직렬화한다.
- 방 나가기는 본인 참여 목록에서 제거하며 작성 내용은 유지한다. 다시 들어갈 수 있다.
- 내 메시지 삭제는 본문과 상품을 지우고 메시지 ID와 답글 연결을 유지한다. 삭제된 메시지는 좋아요를 추가할 수 없다.
- 방 삭제는 논리 삭제이며 목록/공유 링크/직접 메시지·게시글 조회에서 숨긴다. 저장 데이터의 영구 파기 기능과는 구분한다.
- 7일이 지나고 다른 사람의 참여 이력과 메시지·게시글이 전혀 없는 사용자 방만 자동 보관한다. 대화가 있는 방은 오래 조용해도 삭제하지 않는다.
- 신고 수로 방을 자동 삭제하지 않는다. 운영자 검토 후 `close_room`으로 폐쇄하고 사유를 표시한다. 폐쇄된 방의 신규 입장·채팅·게시글·댓글은 서버에서 막는다.

## 태그 운영 결정 기준
- 추가: 방 제목/검색어에서 기존 태그가 설명하지 못하는 주제가 반복될 때 운영자가 검토한다.
- 통합: 의미와 실제 대화가 겹칠 때 별칭을 매핑한다. 기존 ID를 바로 삭제하지 않는다.
- 축소: 최근 30일 선택·검색·대화 및 입장→첫 대화→재방문을 함께 검토한다. 숫자가 적다는 이유만으로 기존 방을 지우지 않는다.
- 현재는 코드 기반 카탈로그를 운영자가 수정한다. 태그 운영 자동화, 태그별 집계 화면, 비활성 30일 추천 가중치 자동 조정은 구현하지 않았다.

## 서버 반영 순서
2026-10-19 점검: 운영 REST에서 `create_room`은 PGRST202 / 함수 없음. `chat_room_list`에도 concerns 필드가 없음. 앱 요청 문제가 아니라 서버 마이그레이션 누락이다.

현재 관리 연결은 `mqsnshnlfwsgabrsmqsz` 프로젝트 SQL 접근 권한이 없어 운영 DB 반영은 미실행이다. 권한 있는 연결에서 마이그레이션 이력을 확인하고, 빠진 기존 `20261019050000_user_rooms.sql`, `20261019060000_concern_keywords.sql` 및 새 `*_room_lifecycle_and_tags.sql`을 순서대로 적용해야 한다. 이미 적용된 파일을 중복 실행하지 않는다.

- Supabase CLI로 생성한 새 마이그레이션 파일을 사용한다.
- pg_cron이 이미 활성화된 프로젝트는 매시 17분 빈 방 보관 작업을 등록한다. 없으면 운영자가 `archive_empty_rooms()`를 별도 스케줄로 호출해야 한다.
- `close_room(room_id, reason)`과 `archive_empty_rooms()`는 service_role 전용이다. 키를 앱에 넣지 않는다.
- 서버 먼저 반영 → 앱/웹 배포 → 실제 방 생성·재접속·다른 기기 참여 후 삭제 차단 검증 → TestFlight 검증 순서.
- 현재 익명 소유권은 기기 secret이다. 앱 삭제·기기 변경 시 계정 기반으로 복구되는 기능은 이번 변경에 포함하지 않는다.
