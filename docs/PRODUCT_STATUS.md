## 픽셀 한복 가이드 온보딩 — 기획 반영·앱 미구현 (2026-10-19)

- **결정**: 하늘색 한복 2D 픽셀 소녀가 신규 방문자에게 인사 → 스킨케어/메이크업 동시 관심 선택 → 분야별 고민 복수 선택 → 현재 공개 방 추천을 안내한다. 피부 타입·톤/개인정보 입력은 필수 아님; 자유 탐색·방 생성·초대 진입을 가리지 않음.
- **관리자 웹**: `/admin` 서비스 기획에 한영 전환·관심사/고민 선택이 가능한 **3단계 미리보기**와 경량 가이드 이미지 1종. 디자인 리뷰·실행 로드맵에도 역할과 실험 기준 추가. 이는 로컬 관리자 시뮬레이션이며 **실제 사용자 데이터·추천 방을 읽거나 저장하지 않는다**.
- **소비자 기능**: 실제 웹/iPhone 온보딩·추천/이벤트·캐릭터 자산 연결·실기기 검증·TestFlight 반영 **미구현 또는 미확인**. 최근 배포 한도 실패는 별도 해결 과제다.
- **후속**: 의상 10종(한복 5종·아이돌 패션 영감 5종)의 사용자 아바타 선택은 P1이며 기본 온보딩 강제 선택에 포함하지 않는다. 제작 자산을 공개 앱에 적용하려면 권리·파일명·성능·익명성 검증이 필요하다.
- **검증할 지표(미측정)**: 캐릭터 유무별 첫 대화 열람, 첫 유의미 발화, D7, 단계별 이탈·스킵, 언어별 오류·접근성. [명세](PIXEL_GUIDE_ONBOARDING.md) · [디자인 리뷰](DESIGN_REVIEW.md).

## 실제 로딩 캐릭터 코드 현황 (2026-10-19)

- **자산/코드 반영**: 웹·iPhone 공통 한복 5종 및 패션 의상 5종의 5×2 투명 픽셀 스프라이트(원본 160×96px, 약 4.8KB). 웹은 `loading-companion.js`, `app.js`, `chat.js`, `style.css`에서 실제 비동기 로딩에 사용하고, iPhone은 `LoadingCompanion.swift`와 `LoadingCharacters.imageset`에 등록.
- **동작 목표**: 400ms 미만 기본 로딩, 이후 캐릭터 보이기 및 약 2.2초 주기 의상 변경, 완료 즉시 종료, 오류 시 재시도, Reduce Motion 정적 표시. 기능은 **코드 반영**, 실제 운영·실기기 결과로 검증 완료 처리하지 않음.
- **관리자**: '디자인 리뷰'에 캐릭터 로딩 시뮬레이션(자동 순환/일시정지/다음 의상)과 새 P0 로딩 UX 리스크를 추가. 개인 로딩 지표는 **미측정**.
- **배포**: 최근 GitHub Vercel status는 `build-rate-limit` 실패. 실제 운영 사이트·App Store/TestFlight 최신 적용은 아직 미확인. iOS 빌드 CI는 별도 결과 필요.
- **분리**: 기존 3단계 피부/메이크업 캐릭터 온보딩과 방 추천은 관리용 시안 단계. 로딩 의상 10종 사용으로 사용자 아바타 10종 선택을 출시한 것으로 표시하지 않음.

| 트래픽 | 기간 신규 순방문자, 고민·K-뷰티 검색 유입, 공유 유입 | **미측정** | 채널별 이벤트 수신·중복 제외 검증 |
| 리텐션 | 첫 유의미 참여율, 신규 참여자 D7 재방문, 반복 대화 | **미측정** | 유입 코호트·채팅 연결·기간 정의 |
| 구매 의도 | 대화→상품 상세, 방문→제휴 클릭률 | **미측정** | 카드 노출·링크 클릭·상품 옵션 일치 검증 |
| 실제 구매 | 제휴 클릭→귀속·승인 주문 전환율, 주문당 금액 | **미측정·정산 미연결** | 주문/취소/반품/승인 원장 대조 |
| 수익성 | **순방문자 1,000명당 승인 제휴 수수료** | **미측정** | 같은 기간 분모와 귀속 매출 범위 일치 검증 |

**우선 검증:** (1) K-뷰티 관심 × 피부·메이크업 고민 고객의 첫 대화와 D7, (2) 고민 해결형·색조 추천형의 제품 링크 전환 차이, (3) 유효 주문·확정 수수료까지의 실제 데이터 연결. 트래픽 규모가 커져도 수익성이 악화되면 성공으로 표시하지 않는다. 목표값과 실험 결과를 임의 작성하지 않는다.

## 기획–전략 퍼널·KPI 협의 현황

2026-10-19 기획팀 제안: [화면 이동·이용시간·구매 퍼널 설계](FUNNEL_KPI_REVIEW.md). **사용자 확정 사항**은 스킨케어·메이크업 복수 선택과 분야별 고민 복수 선택, **누구나 방 자유 생성**, 생성된 방 가운데 고민에 맞는 방 추천이다. 정해진 방으로만 연결하거나 방 생성 허가를 추천에 종속시키지 않는다.

| 항목 | 전략 목표와 기획 연결 | 현재 상태 |
|---|---|---|
| 유입·온보딩 | 방문→관심사 복수 선택/건너뛰기→첫 콘텐츠 | 기획 정의, 이벤트 수신 미검증 |
| 방 발견 | 추천 / 전체 검색 / 공유 유입 / 생성 경로별 방 입장률 | 기획 정의, 실제 추천 서비스 미구현 |
| 자유 생성 | 방 생성 시작→완료→다른 이용자 최초 참여·답변 | 기획 정의, 실제 기능·남용 방어 별도 검증 |
| 이용시간 | 방이 가시·포커스 상태인 유효 체류의 중위값/p75, 첫 발화·답변·D7 | 계측·유효 기준·목표치 미확정 |

## 계측 준비 현황

코드 점검 범위: `dist/events.js`, `dist/chat.js`, `dist/app.js`, `ios/Alimi/Events.swift`, `Community.swift`, `Chat.swift`, `Views.swift`, `Models.swift`. **호출 코드가 있다는 뜻이며 서버 수신 성공을 확인한 것은 아니다.**

- 기존 호출: community_open, post_view, post_create, comment_create, chat_join/chat_send, product_card_click, post_save, product_view, wishlist_add, merchant_click 등. 이벤트 이름이 enum/허용 목록에 있는 것과 실제 호출 경로가 있는 것도 구분한다.
- 미검증: 서버 허용·수신·집계, 중복/실패, 테스트 트래픽 제외, 플랫폼별 속성 일치, 기기 식별자의 한계, 동의·보존 범위.
- 추가 정의 필요: 유용성·선택 도움, 상품 카드 노출, 운영 시간, 확정 주문/정산 연동. 이번에는 이벤트·DB·조회 권한을 변경하지 않았다.
- target_price_set·notification_opt_in 같은 과거 이벤트 이름/데이터는 현재 KPI에서 제외한다. 남아 있는 이벤트 선언이 소비자 기능 재도입을 뜻하지 않는다.
