# 제휴 데이터 사용권 검토와 외부 데이터 엔진 설계

검토일: **2026-10-21 (KST)**. 공개 1차 자료 기준이며 법률 의견·위반 없음 보증이 아니다. 실제 계정에서 수락한 판본, 개별 광고주 Engagement/Insertion Order, 비공개 피드/API 조건은 대조하지 못했다. 이 문서는 **분석·제안만** 하며 수집·학습·판매·배포를 승인하거나 구현하지 않는다.

## 1. 핵심 결론

제휴 승인은 상품을 홍보할 수 있는 관계를 만드는 것이지, 판매처의 모든 데이터를 수집하여 별도 분석사업에 쓰는 포괄적 허락이 아니다. 반대로 모든 집계가 금지된다고 단정할 근거도 없다. **출처 × 필드 × 사용 목적 × 채널 × 보관 기간**별로 판단해야 한다.

설문만으로 사업을 구성할 필요는 없다. 공식 피드의 허용 범위, 별도 분석 라이선스, 브랜드 직접 공급, 재배포 권한을 가진 데이터 공급자를 조합하는 외부 데이터 엔진이 가능하다. 다만 지금 확보한 근거로 유료 트렌드 API나 모델 학습을 켤 수는 없다.

*Stylevana ○/×는 공개 프로그램 설명·색인 약관에 따른 **잠정 판단**이다. 공개 약관의 비정상 템플릿 문구 때문에 실제 수락본 대조가 필수다. OY의 ○도 공개 일반계약의 지정 소재에 한정한다. Sephora의 ○는 공식 프로그램이 배너·creative 제공을 안내한다는 근거이며 비공개 계약 전체를 읽었다는 뜻이 아니다.

**실무적으로:** 공식 제공 링크·홍보물을 써서 제휴 쇼핑 기능을 만드는 경로는 있다. 그러나 그 권리를 그대로 유료 트렌드 사업으로 확장하면 안 된다. 현재 차이는 “전부 안 됨”이 아니라 **홍보는 기존 경로, 외부 분석은 권리 범위를 추가 확보할 경로**라는 것이다.

**계정 상태는 권리 상태와 별도:** 작업 기록상 Stylevana 공식 피드 수신 이력 있음, OY 신청 대기, Sephora 신청 메일 후 대기, Ulta 계정/사이트 확인 단계의 최종 신청 상태 불확실. Coupang 현 계정 승인·API 권한은 이번 검토에서 확인하지 않았다. 가입 승인 여부는 이 문서의 공개 약관 조사로 갱신하지 않는다.

## 4. 외부 데이터 기반 엔진의 실행 가능한 경로

아래는 **후보 설계**이지 현 계약으로 허용됐다는 판단이 아니다.

1. **공식 commerce feed 층:** 허가된 상품 ID·옵션·현재 가격·재고만 수집하고 출처/시각을 보존. 이미지·설명은 별도 권리. 추적 링크 생성권과 데이터 재이용권도 분리.
2. **분석용 외부 소스 층:** 광고주와 기간별 가격·재고·랭킹 변화 집계 및 공개/상업화를 명시한 추가 라이선스 협의, 또는 그러한 권리를 실제 보유한 데이터 공급자/브랜드 직접 공급 검토. 공급자의 “공개 웹 데이터” 주장만으로 충분하지 않다.
3. **공개 통계·검색 수요 층:** 상업 재사용이 명시된 공공 통계나 계약된 검색/소셜 집계 API를 소스별 심사 후 연결. 오픈 API라는 이름만으로 재판매권을 추정하지 않는다.
4. **자체 행동 층:** 서비스 내 조회·저장·판매처 클릭 및 동의받은 커뮤니티 경험. 설문은 보조 신호다. 사용자 동의/보유기간과 네트워크 실적 이용권을 별도 관리.
5. **결합 층:** 외부 노출 변화, 재고 변화, 검색 관심, 자체 클릭을 각각 독립 지표로 표시. 랭킹≠판매량, 클릭≠구매, 일부 판매처≠시장 전체. 국가/통화/카테고리/수집 시점·분모·대표성 한계를 함께 공개. 권리 없는 원본을 집계로 세탁하지 않는다.

첫 후보는 Stylevana 공식 피드의 **어떤 수치 필드를 어떤 기간/목적으로 파생 분석할 수 있는지** 확인하는 것이다. 승인 대기 업체 전부를 기다리는 것보다 좁은 허가를 확보한 한 소스로 실증한 뒤 확장할 수 있다. 계약 미확인 소스로 일단 크롤링부터 시작하지 않는다.

## 5. 제안: 데이터 권리 레지스트리와 fail-closed 게이트

다음은 구현 요청 전 검토용 설계다. 문서 추가만으로 런타임 보호가 생기지 않는다.

- 키: source/retailer/market + field/asset + acquisition_method + contract_version.
- 근거: public_evidence_url, clause, retrieved_at, accepted_version_verified, reviewer, approval_expires_at. 비공개 계약 원문·계정 토큰은 Git에 넣지 않고 접근 제한 저장소의 내부 참조만 사용.
- 권한을 독립 기록: acquire, display_web, display_native, onboarding, transform, retain_history, aggregate_internal, publish_derived, paid_report, redistribute_api, ai_inference, ai_training.
- 값: granted / denied / unknown / conditional. 조건에는 기간·지역·채널·재허락·표시·변경제한.
- 정책: required permission이 unknown/denied/expired면 해당 작업 차단. 광고주 승인과 데이터 권리 통과를 AND로 평가. 권리 확인 전 원본 수집도 off.
- lineage: 파생 지표마다 원천 레코드와 권리 버전을 연결. 한 소스 권한이 다른 소스로 전염되지 않는다.
- 종료/철회: 수집·공개 즉시 차단할 수 있는 소스 스위치, CDN/모바일 번들/임베딩/백업까지 삭제 범위와 시한 기록. 파생물을 계속 보유할 수 있는지는 계약별 판단.
- 검증: unknown, 기간 만료, 웹 전용→앱 요청, 원천 철회→파생 공개 차단, API 재배포 불허, 이미지와 수치 권리 분리 사례를 테스트.

현재 준비 코드는 [PR155](https://github.com/yohan4477/Alimi/pull/155)에 별도 존재한다. 이 문서는 그 코드의 적용·배포를 주장하지 않는다. 기존 방향은 [COMMUNITY_COMMERCE.md](COMMUNITY_COMMERCE.md) 참고. **D-012의 소비자 가격이력/목표가/알림 제외를 변경하지 않으며**, 연구용 이력 설계가 소비자 기능 부활을 의미하지 않는다.
