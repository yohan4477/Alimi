# PRD 09 — Beauty Pick 방 생성·투표 v0.4
작성: 2026-10-22 · 상태: **기획 정책 기준 채택 / 코드·서버·실사용 검증 전**

## 목적
일반 대화의 자유를 유지하면서 필요할 때만 A/B 투표로 의견을 모으고 그 이유를 자유롭게 대화한다. 브랜드 v0.3 / 경쟁 전략 v0.4 기준.

## 방 생성 CX (하나의 화면)
1. **대화 시작 / 투표로 의견 묻기** 중 선택. 기본적인 대화방은 투표 없이 생성 가능.
2. 투표 선택 시 질문과 A/B 선택지를 입력하고, 참여자가 무엇을 기준으로 고를지 선택한다: **자신의 선호(preference)** 또는 **질문자의 상황(context)**.
3. 질문자의 상황 설명은 선택 사항. 맥락형은 입력된 설명 외에 질문 본문에 맥락이 있는지 안내할 수 있으나 피부 프로필·나이 등을 강제하지 않음.
4. 라이브 미리보기를 보고 방 개설. 개설 이후 투표는 추가·교체하지 않음. 자유 채팅은 언제나 가능.

## 결정된 기능 정책
- 방 유형: `chat`(투표 없음) / `poll`(투표 있음).
- **투표방은 방당 투표 하나만** 존재. 방 개설 시 생성자가 설정하고, 대화 중 투표를 추가하거나 두 번째 투표를 생성할 수 없음.
- 투표 기준: `preference`(참여자 자신의 취향·선호) / `context`(질문자의 상황·필요를 고려).
- 투표와 경험 공유는 별개: 투표자에게 직접 사용 경험이 있다고 가정하지 않음.
- 참여는 선택. 투표하지 않고 채팅하거나 결과를 확인하는 동작을 지원하며 결과 공개 규칙은 UI로 명확히 안내.
- 작성자만 초기 설정. 운영 중 변경/종료/삭제 권한 및 투표 변경 허용 여부는 서버 권한 정책으로 별도 확정.
- 새 메인 상단/하단 탭을 만들지 않음.

## 결과 표시와 해석
- `preference`: 응답자들이 자신의 선호로 A/B를 선택한 비율.
- `context`: **질문자의 제시된 조건을 고려해** 응답자들이 A/B를 선택한 비율. 응답자가 질문자와 '비슷한 사람'이라는 뜻이 아님.
- 서로 다른 기준의 투표 비율을 한 추천 점수로 합산하지 않는다.
- 숫자·비율은 서버에서 확인된 실제 데이터만 출력. 0표·실패·마감·응답 적음 상태 구분.
- 상황 설명만 있고 실제 질문의 기준이 없다면 UX로 보완 안내. 피부 타입·효능·결과 동일성을 단정하지 않음.

## 채팅방 UI
- 일반 채팅방은 기존 대화만 표시. 투표 바 없음.
- 투표방은 상단에 **해당 방의 단 하나의 투표**를 작고 접을 수 있는 영역으로 표시. 선택 시 A/B 카드·결과 열기. 채팅은 중심 영역.
- 투표에 대한 선택 이유는 채팅 메시지로 기록 가능, 원본 투표/선택지 연결. 경험자 후속 질문과 알림 거부 허용.
- 대화가 길어져도 투표 1개에 직접 접근할 수 있고, 이미 읽던 메시지·입력 초안 위치를 잃지 않음.
- 투표 종료 후 최종 결과는 남되, 진행 중이라고 표시하지 않음.

## 데이터 모델 제안 — DB 미확정
Room(id,room_type ['chat','poll'],...)
Poll(id,room_id UNIQUE,creator_id,question,voting_basis ['preference','context'],context_text?,status,created_at,...)
PollOption(id,poll_id,position,label,product_variant_id?,image_ref?)
Vote(id,poll_id,option_id,voter_id,created_at,...)
PollMessageRef(poll_id,message_id,option_id?)
PollOutcome(poll_id,author_id,selected_option_id?,observed_at?,...)
방당 Poll 0..1 제약은 데이터베이스 UNIQUE 및 서버 트랜잭션/권한에서 동시 요청까지 보장. 무단 이미지 재사용 금지.

## 수용 기준
1. 일반 채팅방 개설 시 투표 입력 없이 완료.
2. 투표방 개설 시 A/B와 판단 기준 입력·설정 확인.
3. 생성자 아닌 사람이 투표 생성 불가; 이미 투표가 있는 방에 2번째 투표 생성 불가.
4. 맥락형에서 설명이 비어도 질문 자체가 맥락을 제공하는지 안내하고, 비밀 프로필을 요구하지 않음.
5. 투표 없이 채팅, 경험 미기입, 기권 또는 결과 확인 가능.
6. 서버 결과만 집계. 선호형/맥락형 해석 라벨이 정확함.
7. 상단 투표 요약은 채팅을 가리지 않으며 키보드/스크롤/딥링크 동작 유지.
8. 신고·차단·투표 조작 방지·자기신고/협찬 표시·지역 경계 확인.
9. 320px/390px 모바일과 접근성 검증.
10. 운영 DB RLS/RPC 및 실제 데이터 모델 감사 전 서비스 적용 금지.

## 가설 검증
일반 질문 vs 선호형 A/B vs 맥락형 A/B: 작성 완료율, 투표 참여율, 이유 있는 응답률, 후속 질문 유용성, 선택 도움/재방문을 비교. 경쟁 우위·구매 결과는 미검증.
