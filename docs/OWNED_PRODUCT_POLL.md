# 너도 갖고 있어? — 사전 개발

브랜치: `feature/owned-product-poll`. 운영 main과 분리. **미출시**.

## 구현
- `dist/owned-poll/index.html`: 모바일 투표 UI (초기 3개 제품, 기존 명화 게임 이미지 참조)
- `api/owned-poll.js`: GET 결과 / POST 선택 및 변경. 동일 기기·제품별 1표. 서명된 익명 쿠키.
- `supabase/migrations/20261023090000_owned_product_polls.sql`: DB 테이블과 제한된 접근 정책.
- `tests/owned-poll.test.js`: 비활성 상태와 접근 제한 기본 검사.

## 출시 전 필수
1. Supabase에 마이그레이션 적용 (현재 **미적용**).
2. Vercel 환경변수 `OWNED_POLL_ENABLED=true`, `OWNED_POLL_COOKIE_SECRET` (32자 이상), `SUPABASE_SECRET_KEY` 설정.
3. 관리자 미리보기와 기능 플래그 온오프 UI 개발. 현재는 환경변수 기반이며 즉시 토글이 아님.
4. 제품 전체 카탈로그 연결, 운영 DB 저장·다중 기기·오류·부하 테스트.
5. 보안 리뷰(서버 키 권한, 남용 및 투표 조작 방지, 데이터 보존), 한국/미국 문구 검토.
6. 사용자에게 노출할 시점에만 main으로 병합, 배포 확인. main에는 아직 없음.

## 계측
필요 이벤트: poll_view, poll_vote_saved, poll_vote_changed, poll_results_view, poll_share_click, poll_error. 운영 게임 100명 KPI 집계와 분리해 수집.

## 출시 기준
승인 없이 활성화하지 않는다. 기존 게임의 CTA, 탐색, 관리자 보드에 진입 버튼을 연결하지 않는다.

## DB 통합 의존성 (2026-10-23 사용자 확정)
- **단일 목적지**: Supabase Alimi 조직 / SeoulBeauty 프로젝트 `mqsnshnlfwsgabrsmqsz`. 신규 투표·게임·계정·집계 데이터는 이 프로젝트만 사용한다.
- **선행 PR**: [#188](https://github.com/yohan4477/Alimi/pull/188) `feat/beauty-game-supabase-20261023` — 게임의 여섯 기존 API, 대체 도메인·집계, 비공개 `beauty_game` 스키마 및 계정 연결 시범 코드가 이미 작성됨. 동일 구현을 #189에서 재작성하지 않는다.
- 본 투표의 `public.owned_product_votes`는 별도 신규 기능을 위한 초안일 뿐이다. 실제 반영 전에 #188의 최종 스키마/게임 세션 구조와 검토해 식별자·보안·집계·마이그레이션 충돌을 방지한다. 기존 투표 익명 쿠키와 게임 세션은 아직 통합되지 않았다.
- Sites D1은 현행 운영 게임이 사용 중이며 **유지**한다. 새로운 D1 테이블, 이벤트, API, 저장구조를 만들지 않는다. D1 삭제·연결 해제·쓰기 전환·역방향 동기화도 수행하지 않는다.
- PR #188 자체는 Draft이고 DB 마이그레이션·운영 전환·역사 데이터 이관이 완료되지 않았다. #189도 별도 Draft로 유지하고, 두 브랜치가 병합되기 전 API/데이터 모델의 호환성을 재확인한다.
- Supabase production SQL 적용이나 플래그 활성화, 운영 배포는 하지 않았다. D1→Supabase의 승인된 컷오버까지 기존 게임 데이터 기록 위치를 변경하지 않는다.

## 5명 사용자 검증 UX 결정
- 필수: 제품을 선택하고 소장/관심 상태 하나만 투표. 한마디 작성은 참여 조건이 아님.
- 선택: 투표 후 한마디 최대 160자. 비워도 참여 완료이며, 사후 작성·수정 가능.
- 한마디는 서버의 비공개 필드에만 저장하며 목록·통계 API로 공개되지 않음. 공개 댓글/후기 기능은 향후 별도 동의·신고·모더레이션 설계 후 검토.
- 지인 5명에게는 자발적인 두 번째 제품 탐색, 질문 행동, 공유 의향을 정성 관찰. 아직 100명 목표를 출시 게이트로 강제하지 않음.
